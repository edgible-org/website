Add your app

You built something, maybe with an AI. Edgible can put it on the internet, keep it running, and, if you want, list it in the card catalog so anyone can run it.

Three things you might want

  • Get it live. An address people can open, with HTTPS and the sign-in you choose, from a computer you control.
  • Keep it running. In a container, with its data kept safe and backed up, so it survives restarts and upgrades. That setup can stay private.
  • Share it. A card in the public catalog, so other people can run your app with one prompt. This one is optional, and it comes last.

Start with your AI

Give your AI the Edgible skill once. We recommend Claude Code; other assistants that read skills work too.

Install the Edgible skill from github.com/edgible-org/card-kit

Then tell it about your app:

I built an app at (your repository or folder). Help me put it on Edgible. Tell me what it needs to go live, and what it needs to become a card in the catalog.

It reads your app and tells you plainly what must change and what would make it better, and offers to build each missing piece. It changes nothing in your app without asking.

What a card needs

Required

  • A public image with a version tag, built for both Intel and Apple Silicon
  • A licence that lets others run it
  • Its settings written down
  • Its port, and where its data lives
  • No secrets in the code
  • Someone who answers for it: a GitHub name

Nice to have

  • A healthcheck
  • Not running as root
  • Secrets that can come from files
  • A note on how to back it up
  • Tagged releases
  • No default password in the files

The skill runs a checker, check-app, and reads you the result. You can run it yourself too: it is in card-kit.

You test it first, on your own Edgible

Before a card reaches us, your AI tests it on a machine of yours, signed in to your own Edgible account. A spare computer or a small virtual machine will do. Nothing of ours is touched, and the result goes into your pull request. Using Edgible this way is the point: you are running your own app on it.

A person at Edgible then reads the card and tests it again on our own machines before it is listed. That is done by hand, so it is not instant.

Who answers for it

Every card in the catalog shows who looks after it. Put your GitHub name on yours and it says Stewarded by you: you review changes to it and fix it if its test fails. Prefer not to? It can be listed with No steward. It is still tested every night, and if its test fails, it is shown dimmed until it passes. Your app stays yours, with your licence and your repository. The card only describes how to run it.

Building with an AI agent that works on its own?

An agent can do all of it. check-app --json tells it what is missing until nothing required is left. It asks you only for what is yours to decide, such as the licence and who the steward is. Then it opens the pull request from a fork. Start from the Edgible skill, the contributing guide, and llms.txt.
